# SPEC 1.3 — Diseño de secciones de producto con foto CDN de prueba

> **Estado:** Implemented
> **Depende de:** SPEC 01, SPEC 1.2
> **Fecha:** 2026-10-13
> **Objetivo:** Rediseñar la página `/templates/[slug]` con las 3 secciones de `screenshots/products/` usando `https://cdn.ferredip.com.mx/fotos/product-example.webp` como foto única de prueba en home y producto.

## Por qué existe este spec

El home del SPEC 1.2 apunta a fotos rotas (claves R2 sin datos reales). El dueño pide una prueba visual temporal con una sola URL CDN repetida en todas las opciones, y vestir la página de producto que hoy es mínima (foto + descripción + PERSONALIZAR) con el lenguaje Etsy/3DJoy de las 3 capturas de `screenshots/products/`, sin abrir carrito, pagos ni editor funcional nuevo.

## Alcance

**Dentro:**

- Cambio de foto a `https://cdn.ferredip.com.mx/fotos/product-example.webp` (verificada el 2026-10-13 con `curl -I`: `200 image/webp`, 34 KB, Cloudflare) en `components/ProductCard.tsx` (home: destacados + todos) y en `app/[locale]/templates/[slug]/page.tsx`, repetida en todas las opciones como prueba temporal, con fallback local obligatorio a `/images/product-example.webp` si la CDN falla o bloquea hotlink. Se sigue usando `ProductImage` / `<img>` existente, sin `next/image` remoto (no se toca `next.config` en este spec).
- Rediseño solo visual de `app/[locale]/templates/[slug]/page.tsx` en 3 secciones, en orden: principal (galería + info) → reseñas → relacionados, como en `1.-main-section.jpg`, `2.-product-review.png`, `3.-other-products.png`.
- Sección principal: galería con una sola imagen grande cuando solo hay foto de prueba (tira de miniaturas y flechas ocultas si `fotos.length === 1`; solo se muestran con 2+ fotos reales en otro spec); columna derecha con precio `MX$` en verde + anterior tachado + `-25 %`, nota de oferta, título, descripción, vendedor Dolphin, badge GRATIS conservado si `esGratis`, botón `Editar diseño` como `Link` real a `/editor/[code]` con estilo nuevo, botón `Añadir al carrito` solo visual (`<button type="button" aria-disabled="true" title="Próximamente">`, sin navegar ni error al pulsarlo), bloque corazón wishlist solo visual, badge `PDF + SVG + DXF` solo visual y provisional, acordeón `Detalles del artículo` (`<details>`) con descripción real + lista fija de archivos incluidos.
- Bloque de reseñas como **muestra etiquetada**: mantiene el estado vacío real (`Aún no hay reseñas`) + etiqueta visible `Datos de muestra` + 3 reseñas fijas por i18n con resumen `4.8 (316)` y dropdown `Ordenar` solo visual; la sección lleva `data-muestra="true"` y no genera `AggregateRating` en el JSON-LD para no envenenar SEO.
- Grid `También podría interesarte`: hasta 8 productos de la misma `category_id` excluyendo el actual, con relleno por `code` del resto del catálogo; si el catálogo total disponible es `<= 1`, la sección se oculta; cada card usa foto CDN de prueba, precio provisional existente y link real a su `/templates/[slug]`.
- Claves nuevas solo en `messages/es.json` + `messages/en.json` (`product.*`, incluyendo `product.muestra.*` para la etiqueta).
- Tokens y estilos en `app/globals.css` reutilizando los del SPEC 1.2 (fondo crema, card, precio verde, tachado).
- Responsive 360px / 768px / desktop: galería apila, columna info debajo, grids 4→2→1, sin scroll horizontal.
- Verificación con `npm run build` + `npm run lint` en verde + capturas manuales 360/768/1280 en ES y EN con chequeo `document.documentElement.scrollWidth <= window.innerWidth`; el implementador usa el MCP de Playwright si lo tiene disponible para navegación, evaluados de overflow y capturas.

**Fuera de alcance (para futuros specs):**

- Carrito, checkout, pagos, wishlist, orden de reseñas y buscador funcionales.

- Franja `ESPACIO PUBLICITARIO`, textos y marca Etsy, `Informar sobre este artículo a Etsy` y `Traducido por Google`.

## Modelo de datos

Esta feature no introduce nuevas estructuras de datos. Reutiliza el modelo del SPEC 01 (`products`, `categories`) y la consulta existente por slug, más constantes de presentación.

```ts
// Solo ilustrativo: lo nuevo vive en constantes + i18n, no en DB
FOTO_PRUEBA_CDN = "https://cdn.ferredip.com.mx/fotos/product-example.webp"; // verificada 2026-10-13: 200 image/webp
FOTO_FALLBACK_LOCAL = "/images/product-example.webp"; // obligatorio si la CDN falla
PRECIOS_PROVISIONALES = { porDefecto: { mx: 116.32, anterior_mx: 155.09, descuento: "25 %" } };
RESENAS_MUESTRA = [/* { nombreKey, fecha, estrellas: 5, textoKey, productoKey } x3, solo i18n, con etiqueta visible */];
ARCHIVOS_INCLUIDOS_FIJO = ["Plantilla PDF", "Archivos de corte SVG", "Archivos de corte DXF", "Instrucciones de montaje"];
```

Convenciones:

- Contenido visible traducible solo en `messages/es.json` + `messages/en.json` (claves `product.galeria.*`, `product.info.*`, `product.detalles.*`, `product.resenas.*`, `product.muestra.*`, `product.relacionados.*`). Las 3 reseñas de muestra también van por claves i18n.
- La URL CDN es temporal y marcada `FOTO_PRUEBA_CDN`; se reemplaza por fotos reales R2 en otro spec. Nada se sube a R2 en este spec.
- Relacionados resuelven por `category_id` del producto actual, excluyen su `id`, rellenan por `code`, y conservan slugs localizados ES/EN. Con `<= 1` producto disponible la sección no se renderiza.
- La sección de reseñas de muestra lleva `data-muestra="true"`, etiqueta visible y queda excluida de `AggregateRating`/rich snippets.

## Decisiones

- **Sí:** las 3 secciones de `screenshots/products/` en este spec. El dueño quiere la página completa vestida de una vez; partirla en 3 specs multiplicaría el cableado.
- **Sí:** URL CDN absoluta repetida como prueba temporal en home y producto (verificada `200 image/webp` el 2026-10-13), con fallback local obligatorio. Descarta mantener solo el fallback local que hoy no cubre la página de producto, y descarta `next/image` remoto sin `next.config` en esta prueba.
- **Sí:** solo se toca `/templates/[slug]` más el origen de foto del home. Descarta rediseñar categoría y editor aquí para no abrir 3 frentes.
- **Sí (temporal):** `Editar diseño` como `Link` real a `/editor/[code]`; solo `Añadir al carrito` queda estético deshabilitado. Descarta ambos inertes porque rompería el embudo home → producto → editor del SPEC 1.2.
- **Sí:** reseñas como muestra etiquetada con `data-muestra`, etiqueta visible y sin `AggregateRating`. Descarta solo-vacío (no valida el diseño de la captura 2), descarta tabla DB (sobrediseño) y descarta muestra sin etiqueta (prueba social falsa / SEO).
- **Sí:** relacionados por misma categoría con relleno por `code` y sección oculta si `<= 1`. Descarta últimos-8 global y grid fijo hardcodeado.
- **Sí:** galería sin tira ni flechas cuando hay una sola foto. Descarta miniaturas y flechas muertas que parecen bug.
- **Sí:** badge GRATIS conservado y badge `PDF + SVG + DXF` solo como provisional visual. Los entregables reales se definen en otro spec.
- **No:** franja publicitaria, marca Etsy ni textos de ferretería. Se copian estilos, no identidad de terceros.
- **Sí:** verificación `build`/`lint` + capturas con chequeo de overflow, con MCP de Playwright si está disponible en la implementación. En esta sesión de spec no hay MCP conectado; exigirlo como único medio bloquearía la verificación.

## Riesgos

| Riesgo | Mitigación |
|---|---|
| La CDN externa cae o bloquea hotlink y rompe todas las fotos | Verificada `200` el 2026-10-13 + constante única `FOTO_PRUEBA_CDN` + fallback local obligatorio probado con CDN bloqueada |
| La foto única repetida llega a producción como si fuera final | Nombre `FOTO_PRUEBA_CDN` + temporalidad declarada; fotos reales en otro spec |
| Reseñas fijas y `4.8 (316)` parecen reales y confunden | Etiqueta visible `Datos de muestra` + `data-muestra` + sin `AggregateRating`; tabla real en otro spec |
| Precios hardcodeados se perciben como reales | Reutiliza `PRECIOS_PROVISIONALES` del SPEC 1.2; precios reales en otro spec |
| Badge `PDF + SVG + DXF` promete entregables inexistentes | Marcado provisional visual; entregables reales en otro spec |
| Tentación de copiar textos/marca Etsy | Criterio explícito: vendedor Dolphin, sin marca Etsy; buscar "Etsy" en el diff |

## Lo que **no** está en este spec

- Fotos finales, R2, columnas de precio y precios reales.
- Carrito, checkout, pagos, wishlist y orden funcionales.
- Tabla de reseñas, envío de reseñas y paginación.
- Cambios en home (salvo origen de foto), categoría, editor, header y footer.
- SEO nuevo, sitemap, hreflang, canonical y JSON-LD nuevos (el JSON-LD además omite imagen de prueba y reseñas de muestra).
- Franja publicitaria y marca Etsy.

Cada uno de esos, si llega, va en su propio spec.
