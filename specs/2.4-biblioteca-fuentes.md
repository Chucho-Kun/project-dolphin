# SPEC 2.4 — Biblioteca de fuentes del editor

> **Estado:** Approved
> **Depende de:** SPEC 02, SPEC 2.1, SPEC 2.2
> **Fecha:** 2026-10-15
> **Objetivo:** Cada `texto-editable-<clave>` elige familia (10 OFL fijas) y peso (Regular/Bold) en el `PanelTexto`, el cambio se ve directo en el canvas, se guarda con `?t=` y sale en el PDF.

## Por qué existe este spec

El editor solo ofrece una tipografía (`Roboto`, lista fija en `lib/texto.ts` con `FUENTES_EDITOR = ["Roboto"]`). El dueño pide una biblioteca seleccionable por texto que cambie lo que se ve en el canvas. Este spec la define de punta a punta y fija la ficha técnica que debe cumplir cada archivo de fuente para funcionar en canvas, guardado y PDF raster.

## Alcance

**Dentro:**

- Biblioteca cerrada de 10 familias Google Fonts OFL: Roboto, Open Sans, Lato, Montserrat, Roboto Condensed, Oswald, Poppins, Inter (sans), Playfair Display (serif) y Dancing Script (manuscrita). Pesos 400 + 700, subsets `latin` + `latin-ext`.
- Archivos WOFF2 autohospedados: carga vía `next/font/google` en `app/[locale]/editor/[code]/page.tsx` con `subsets: ["latin", "latin-ext"]` y `display: "swap"` (el build emite WOFF2 locales; cero `<link>` a CDN en runtime). Las 10 familias se cargan siempre (10 llamadas estáticas combinadas en el `className` del `main`); el coste de descargar las no usadas se acepta en v1.
- Catálogo nuevo en `lib/fuentes.ts`: const con `id` estable, familia, categoría, pesos y clase de `next/font`; `lib/texto.ts` reexporta `FUENTES_EDITOR` desde ahí, sin duplicar la lista.
- Selectores por texto en `components/editor/PanelTexto.tsx`: familia (`<select>` nativo en texto plano, sin preview —la muestra es el propio canvas) + peso (Regular/Bold); viven dentro del flotante del SPEC 2.2, sin cambiar su mecánica. Sin itálica en v1.
- Aplicación en `components/editor/PlantillaSvg.tsx`: el `fontFamily` del nodo usa familia + peso del ajuste; se espera a `document.fonts.load()` de esa familia y peso antes de medir/pintar para que el auto-shrink mida con la fuente real.
- Persistencia: `AjusteTexto.fuente` es el `id` kebab del catálogo y `peso` es campo nuevo opcional (`400 | 700`, default 400); la whitelist en `app/api/customizations/route.ts` acepta los 10 ids más el alias legado `"Roboto"` (se normaliza a `"roboto"`; cualquier otro valor se rechaza con `ajustes-no-validos`) y el default de `EditorShell.tsx` pasa a `"roboto"`.
- Diseños viejos sin `fuente` o sin `peso`: fallback a `roboto` / 400 sin error ni migración (igual que `x/y` opcionales del SPEC 2.1).
- Fuente visible en el PDF: `lib/pdf.ts` incrusta `@font-face` con el WOFF2 en base64 de la familia y peso usados dentro del clon serializado (el modo `<img>` del raster no ve las fuentes del documento, así que sin incrustación el PDF saldría en fallback); verificación visual + regla, sin jsPDF vectorial.
- Claves i18n solo en `messages/es.json` + `messages/en.json` (etiquetas de familia y peso, reutilizando `editor.panelTexto.*`).

**Fuera de alcance (para futuros specs):**

- Subida de fuentes por el usuario (TTF/OTF propios) o catálogo Google Fonts abierto sin curaduría.
- Undécima familia, fuentes variables, pesos distintos de 400/700, cursivas (italic) o subsets emoji/CJK.
- Tabla `fuentes` en DB o gestión del catálogo sin deploy.
- Grid visual de muestras, preview dentro de las opciones o buscador (la muestra es el canvas).
- Cambios en auto-shrink [60 %,100 %], medición de slot, alineación, mover/escalar, selección, flotante, Guardar, `?t=`, subidas, rate-limit, home, producto, SEO o sitemaps.

## Modelo de datos

Esta feature no crea tablas, migraciones ni campos nuevos salvo el `peso` opcional en ajustes. Reutiliza `customizations.ajustes` del SPEC 02 y solo agrega el catálogo en código más estado efímero de carga:

```tsx
// lib/fuentes.ts — nuevo, única fuente de verdad del catálogo
export type CategoriaFuente = "sans" | "serif" | "manuscrita";
export type EntradaFuente = {
  id: string;          // kebab estable, p. ej. "open-sans" — es lo que se persiste
  familia: string;     // nombre CSS, p. ej. "Open Sans"
  categoria: CategoriaFuente;
  clase: string;        // className de next/font por familia (400 + 700)
};
export const FUENTES_EDITOR: EntradaFuente[] = [
  { id: "roboto", familia: "Roboto", categoria: "sans", clase: "..." },
  { id: "open-sans", familia: "Open Sans", categoria: "sans", clase: "..." },
  { id: "lato", familia: "Lato", categoria: "sans", clase: "..." },
  { id: "montserrat", familia: "Montserrat", categoria: "sans", clase: "..." },
  { id: "roboto-condensed", familia: "Roboto Condensed", categoria: "sans", clase: "..." },
  { id: "oswald", familia: "Oswald", categoria: "sans", clase: "..." },
  { id: "poppins", familia: "Poppins", categoria: "sans", clase: "..." },
  { id: "inter", familia: "Inter", categoria: "sans", clase: "..." },
  { id: "playfair-display", familia: "Playfair Display", categoria: "serif", clase: "..." },
  { id: "dancing-script", familia: "Dancing Script", categoria: "manuscrita", clase: "..." },
];
export const FUENTE_DEFAULT = "roboto";
export const PESO_DEFAULT = 400 as const;
/** Alias legado: los ?t= viejos traen "Roboto" (familia con mayúscula). */
export function normalizarFuente(id: string): string { /* "Roboto" → "roboto"; resto intacto */ }
export function esFuenteValida(id: string): boolean { /* normalizado ∈ catálogo */ }
export function resolverFuente(id: string): EntradaFuente { /* desconocida → Roboto */ }
```

```tsx
// lib/texto.ts — fuente pasa a id kebab; peso nuevo opcional
export type AjusteTexto = {
  contenido: string;
  tamano: number;
  color: string;
  fuente: string;      // id del catálogo; ausente o desconocido ⇒ "roboto"
  peso?: 400 | 700;    // ausente ⇒ 400 (diseños viejos abren en Regular)
  x?: number;
  y?: number;
};
```

Convenciones:

- El `id` persistido nunca es el nombre con espacios: solo minúsculas y guiones, inmutable aunque cambie la familia.
- `PlantillaSvg.tsx` pinta `fontFamily = "<familia>", Roboto, sans-serif` con `fontWeight` del peso, y mide el auto-shrink solo tras `document.fonts.load("<peso> 16px \"<familia>\"")`; si falla, mide y pinta con Roboto 400 sin error.
- La página del editor combina las 10 clases de `next/font` en el `main`; el canvas hereda todas las familias y cada texto usa la suya por `font-family` inline.
- La API acepta los 10 ids más el alias `"Roboto"` (normalizado a `"roboto"` en servidor); cualquier otro valor rechaza el payload con `ajustes-no-validos`, igual que hoy.
- El export a PDF incrusta en el clon un `<style>` con `@font-face` (URLs `data:font/woff2;base64`) solo de las familias y pesos usados; el resto del flujo raster (`data-ui` fuera, JPEG 300 DPI) no cambia.

**Ficha técnica que debe cumplir cada archivo de fuente (respuesta a lo pedido):**

- **Formato:** WOFF2 como único formato servido (compresión ~30 % mejor que WOFF/TTF); el build de `next/font/google` lo emite solo, sin TTF/OTF en `public/`.
- **Subsets obligatorios:** `latin` + `latin-ext` (cubre `ñÑ áéíóúü ÁÉÍÓÚÜ ¿? ¡!`). Sin `latin-ext` los caracteres extendidos caen a fallback y rompen el diseño.
- **Pesos:** 400 (Regular) + 700 (Bold) por familia, nada más en v1. Cada peso es un archivo WOFF2 separado con su `unicode-range` por subset.
- **Sin italic:** ningún archivo italic en v1; `font-style` siempre normal. Si un SVG trae italic por defecto, se pinta normal.
- **Licencia:** OFL (SIL Open Font License) verificable en la ficha de Google Fonts; permite incrustar en el PDF impreso sin coste ni atribución en el documento.
- **Carga:** `display: "swap"` siempre (texto visible con fallback, sin bloqueo ni FOIT); alcance limitado a la página del editor para no tocar home/producto.
- **`unicode-range` por subset:** cada archivo declara su rango para que el navegador descargue solo el subset usado (el `latin` primero, `latin-ext` bajo demanda).
- **Nombre y métricas estables:** familia con `font-family` único, altura de x y ascendentes compatibles con texto corrido en tarjetas (descarta display extremas ilegibles a 8–12 px); verificación manual de `ñ` y tildes a tamaño mínimo antes de entrar al catálogo.
- **Sin dependencias externas en runtime:** ningún `@import` ni `<link>` a `fonts.googleapis.com`; todo sale del build (el PDF raster no depende de red).

## Plan de implementación

1. Crear `lib/fuentes.ts` con las 10 familias (ids kebab, Roboto primera) + `normalizarFuente`/`esFuenteValida`/`resolverFuente`, y hacer que `lib/texto.ts` reexporte `FUENTES_EDITOR` desde ahí y añada `peso?: 400 | 700` a `AjusteTexto`. Verificación: `npm run build` compila sin import roto y ningún otro módulo define su propia lista.
2. Cargar las 10 familias en `app/[locale]/editor/[code]/page.tsx` vía `next/font/google` (una llamada estática por familia) con `subsets: ["latin", "latin-ext"]`, `weight: ["400", "700"]`, `style: ["normal"]`, `display: "swap"`, clases combinadas en el `main` de la página. Verificación: abrir `/es/editor/FIG-001-A-BETA` no emite petición a `fonts.googleapis.com` ni `fonts.gstatic.com` en la pestaña Red.
3. Selectores en `PanelTexto.tsx`: familia (`<select>` plano con los 10 nombres) + peso (Regular/Bold); el cambio llama `onCambio` con `id` y `peso`. Verificación: elegir otra familia o peso repinta ese texto en el canvas y los demás textos no cambian.
4. Sincronizar medición con carga en `PlantillaSvg.tsx` + `lib/texto.ts`: esperar `document.fonts.load()` de familia y peso antes de medir el auto-shrink; si la fuente falla, medir y pintar con Roboto 400. Verificación: texto largo con fuente o Bold recién elegidos no desborda el slot ni trunca de más tras recargar.
5. Whitelist en `app/api/customizations/route.ts` (10 ids + alias `"Roboto"` normalizado, resto 400 `ajustes-no-validos`), validación de `peso` (`400 | 700`, ausente válido) y default `"roboto"` en `EditorShell.tsx`; textos viejos sin `fuente`/`peso` abren en Roboto/400. Verificación: Guardar entrega `?t=` y reabrir restaura familia y peso por texto; un PUT con `fuente` inventada se rechaza; un PUT con `"Roboto"` legado se acepta y se lee como `roboto`.
6. Incrustación de fuentes en `lib/pdf.ts`: el clon serializado lleva `<style>` con `@font-face` en base64 de las familias y pesos usados (obtenidos de las URLs locales de `next/font` vía `fetch` + `FileReader`, igual que `incrustarImagenes`). Verificación: exportar con Roboto, Playfair Display Bold y Dancing Script muestra las tres en el PDF y la página mide lo declarado ±1 mm.
7. i18n ES/EN (etiquetas de familia y peso en `editor.panelTexto.*`), `npm run build` + `npm run lint` en verde, capturas 360/768/1280 sin scroll horizontal.

## Criterios de aceptación

- [ ] El desplegable de `PanelTexto` lista las 10 familias por su nombre (texto plano), más el selector Regular/Bold, en ES y EN.
- [ ] Elegir familia o peso repinta solo ese `texto-editable-<clave>` en el canvas; el resto del diseño no cambia.
- [ ] Cada familia declara pesos 400 + 700 y subsets `latin` + `latin-ext`; la `ñ`, las tildes y `¿?¡!` se pintan con la familia elegida (sin fallback visible).
- [ ] En runtime no hay petición a `fonts.googleapis.com` ni `fonts.gstatic.com` (todo WOFF2 sale del build).
- [ ] El auto-shrink mide con familia y peso reales: un texto largo en Bold no desborda tras cambiar ni tras recargar la página.
- [ ] Guardar persiste familia y peso por texto y reabrir con `?t=` los restaura en cada texto.
- [ ] Un diseño guardado antes de este spec (sin `fuente` ni `peso`) abre en Roboto Regular sin error ni aviso.
- [ ] Un payload con `fuente: "Roboto"` legado se acepta y se lee como `roboto`; uno con fuente inventada se rechaza con `ajustes-no-validos`.
- [ ] Un `peso` distinto de 400/700 se rechaza; un `peso` ausente se lee como 400.
- [ ] El PDF muestra cada texto con su familia y peso elegidos y mantiene medidas ±1 mm.
- [ ] Si una fuente falla al cargar, el texto se pinta en Roboto 400 sin romper el canvas ni el guardado.
- [ ] Ningún string UI nuevo vive fuera de `messages/es.json` + `messages/en.json`.
- [ ] En 360px, 768px y 1280px no hay scroll horizontal (`scrollWidth <= innerWidth`).
- [ ] `npm run build` y `npm run lint` pasan en verde.
- [ ] El diff no toca validación de imágenes, firma mágica, rate-limit, R2, tablas, Guardar, selección, flotante, home, producto, SEO ni sitemaps (salvo la whitelist de fuentes y el `peso` en la ruta de customizations, y la incrustación en `lib/pdf.ts`).

## Decisiones

- **Sí:** 10 familias cerradas fijadas por el dueño (8 sans + Playfair Display serif + Dancing Script manuscrita), pesos 400+700, `latin`+`latin-ext`. Descarta Noto Sans JP (CJK pesadísima, contra la exclusión CJK de v1) y Raleway (novena sans redundante; su hueco lo ocupa la manuscrita que pide la papelería).
- **Sí:** WOFF2 autohospedado vía `next/font/google` con `display: "swap"`, las 10 siempre cargadas (grilling: 10 llamadas estáticas, coste aceptado en v1). Descarta CDN con `<link>` (exige internet y frena el PDF offline) y TTF/OTF crudos (más pesados, sin `unicode-range` por subset).
- **Sí:** selectores por texto (familia + peso) con `<select>` plano y sin preview (grilling: los `<option>` nativos ignoran `font-family`, el criterio con preview era inimplementable). La muestra es el canvas. Descarta fuente global (impide combinar título y cuerpo) y listbox custom (accesibilidad y QA propios para v1).
- **Sí:** campo `peso` opcional con default 400 (grilling: sin campo, los 700 descargados eran peso muerto). Descarta peso obligatorio con migración (reescribe datos sin pedirlo).
- **Sí:** incrustar `@font-face` en base64 en el clon del PDF (grilling: el raster vía `<img>` en `lib/pdf.ts:109-113` no ve las fuentes del documento; sin esto el criterio PDF era falso). Descarta PDF en fallback (el impreso mentiría respecto al canvas).
- **Sí:** alias legado `"Roboto"` → `"roboto"` en cliente y servidor (grilling: la validación rechaza lo desconocido con 400 y los `?t=` viejos traen `"Roboto"`; sin alias, regrabar diseños viejos se rompería). El resto sigue rechazándose.
- **Sí:** la fuente se guarda en `ajustes` y sale en el PDF raster. Descarta solo-visual (el invitado perdería su elección al reabrir) y guardar-sin-PDF (el impreso mentiría respecto al canvas).
- **Sí:** catálogo como const en `lib/fuentes.ts`, sin tabla DB. Descarta JSON público (segunda fuente de verdad sin tipado) y tabla DB (migración y admin para una lista que cambia por deploy).
- **Sí:** fallback Roboto 400 para diseños viejos, fuentes desconocidas y fallos de carga. Descarta migración al abrir y aviso al usuario.
- **Sí:** sin italic en v1 (el Roboto actual cargaba italic; se retira). Descarta conservar solo la italic de Roboto (asimetría sin UI que la exponga).
- **Sí:** verificación PDF visual + regla. Descarta comparación de píxeles (frágil ante antialiasing).
- **No:** subida de fuentes por usuarios, undécima familia, variables, italic, CJK, gestión sin deploy, ni grid de muestras (van en su propio spec si llegan).

## Riesgos

| Riesgo | Mitigación |
|---|---|
| Una familia no trae `latin-ext` y los extendidos caen a fallback | Verificación manual de `ñ` y tildes a tamaño mínimo antes de entrar al catálogo; sin subset completo no entra |
| FOUT al cambiar de fuente o peso (salto de métricas y re-shrink) | `display: swap` + remedición tras `document.fonts.load()` con peso; el slot manda, el texto nunca desborda |
| Payload con `fuente` inventada desde cliente | Whitelist idéntica en cliente y `app/api/customizations/route.ts` (10 ids + alias); lo demás es 400 |
| El base64 de fuentes infla la memoria del raster en móvil | Solo se incrustan las familias y pesos usados, no las 10; el tope de lado mayor y el `revokeObjectURL` siguen vigentes |
| Las 10 familias se descargan aunque no se usen | Coste aceptado en v1 (WOFF2 + `unicode-range` por subset); si pesa, otro spec lo hace bajo demanda |
| `id` con espacios o mayúsculas rompe `fontFamily` y persistencia | `id` kebab-case inmutable; la familia CSS vive solo en el catálogo, nunca en el payload |

## Lo que **no** está en este spec

- Subida de fuentes por el usuario.
- Undécima familia, variables, pesos fuera de 400/700, cursivas o subsets emoji/CJK.
- Tabla de fuentes en DB o gestión sin deploy.
- Grid visual de muestras, preview en opciones o buscador.
- Cambios en auto-shrink, medición, alineación, mover/escalar, selección, flotante, Guardar, `?t=`, subidas, rate-limit, PDF (salvo incrustación de la fuente), home, producto, SEO o sitemaps.

Cada uno de esos, si llega, va en su propio spec.
