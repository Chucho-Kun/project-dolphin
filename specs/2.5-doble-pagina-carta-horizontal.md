# SPEC 2.5 — Doble página carta horizontal con normalización en seed

> **Estado:** Approved
> **Depende de:** SPEC 02, SPEC 2.1, SPEC 2.2, SPEC 2.3, SPEC 2.4
> **Fecha:** 2026-10-16
> **Enmienda:** 2026-10-16 — las imágenes incrustadas (`<image data:>`) de la capa de diseño **son parte del diseño**: se conservan y deben verse en el editor e imprimirse en el PDF (antes se eliminaban).
> **Objetivo:** El producto BOD-001 (carta horizontal, 2 páginas) normaliza sus SVG de diseñador en el seed, edita zonas —incluidos diamantes rotados— y textos por página, y descarga un único PDF de 2 páginas con las medidas declaradas.

## Por qué existe este spec

El dueño editó en Illustrator un diseño de 2 páginas en carta horizontal (`public/editor/BOD-001/diseno-01.svg`, `diseno-02.svg`) con capas amables (`fotos-editables`, `textos`) y una capa de diseño no editable. La plataforma solo entiende el contrato por elemento (`zona-editable-N`, `texto-editable-<clave>`, medidas en mm) y solo soporta 1 SVG por producto con PDF de 1 página. Este spec cierra ambas brechas: normalización automática en ingesta (el dueño no edita XML) + editor y PDF multipágina. Definido por clarificación el 2026-10-16 (normalización en seed, diamantes como zonas de foto, re-exportar puede re-encuadrar guardados).

## Alcance

**Dentro:**

- Normalización en seed (`lib/svg.ts` + `scripts/seed.ts`): capas amables → contrato, por página, con reporte impreso. Nombres exactos con guiones y sin espacios (Illustrator convierte espacios en `_`: tu capa salió como `lineas_y_diseno`; "fotos editables" no matchearía `fotos-editables`).
- Medidas: si el `<svg>` trae `width`/`height` en mm válidos se respetan y se reportan; si no (tus BOD-001 solo traen `viewBox`), se inyectan los de config (carta horizontal: 279.4×215.9 mm) preservando el `viewBox`.
- Slugs de texto desde el contenido: minúsculas, sin acentos, no-alfanum → guion, recorte a ≤30 car. en límite de guion, sufijo `-2` ante colisión (límite duro del servidor: 64 car. tras el prefijo). Esperado BOD-001: `retrospectiva`, `2021`, `lorem-ipsum-dolor-sit-amet`.
- Imágenes incrustadas: los `<image>` con `data:` de la capa de diseño se **conservan inline** (son parte del diseño y deben imprimirse); el reporte lista los bytes incrustados por página. Inline por autocontención y seguridad del raster del PDF (sin CORS).
- Errores de normalización (no adivinan): `zona-duplicada` (el seed imprime sus coordenadas y esa página no se sube: conserva su key en `null`, el resto continúa), `contrato-mixto` (zonas explícitas + capas amables a la vez: el dueño elige un sistema), `sin-capas-editables` (lista los `id` de `<g>` encontrados para diagnosticar el nombre).
- Canvas (`components/editor/PlantillaSvg.tsx`): medición de zonas transform-aware + `clipPath` clonando el marcador original (diamantes recortan en diamante). Contorno de selección sigue siendo bbox rectangular (UI solamente).
- Multipágina: `products.plantilla_svg_key_2` (página 2), `pagina?: number` en `customizations.imagenes[]` y `ajustes.imagenes[]`/`ajustes.textos[]` (ausente ⇒ `1`, normalizado en `cargarReapertura`; sin migración de datos). `app/api/uploads` no se toca: la key ya lleva UUID único y no puede colisionar entre páginas; la página viaja solo en el payload de customizations (validada `1|2` como los opcionales del SPEC 2.1).
- Servidor (`lib/plantilla.ts`): carga de páginas como array, cada página valida mm + ≥1 zona por separado; fallback local `public/editor/BOD-001/diseno-01.svg` y `diseno-02.svg`.
- Editor (`EditorShell` + `PlantillaSvg` por página): selector página 1/2, estado independiente por página, `svgRef` por página para el raster.
- PDF (`lib/pdf.ts`): raster por página + `jsPDF.addPage` → PDF único de 2 páginas, cada una 279.4×215.9 mm ±1 mm (apaisado ya soportado).
- Seed BOD-001: el producto ya existe (`seed.ts`) con `plantillaSvgKey: null`; se le asignan las 2 keys + config de normalización. Idempotencia 2x como hoy.
- i18n: una sola clave `editor.pagina.etiqueta` ("Página {n}" / "Page {n}") en `messages/es.json` + `messages/en.json`.

**Fuera de alcance (para futuros specs):**

- 3+ páginas genéricas (cuando lleguen, `plantilla_svg_key_2` migra a array).
- Mapeo por geometría entre versiones (re-exportar puede re-encuadrar guardados — decisión aceptada).
- Contorno de selección con forma de diamante (solo bbox rectangular).
- Auto-shrink multilínea por `tspan` (el párrafo de diseno-02 encoge como bloque).
- Itálicas de Illustrator (se aplanan a normal, SPEC 2.4).
- Subida de SVG por UI, cambios en uploads (validación, firma mágica, rate-limit, topes: 19 fotos ≤ 20 existentes), catálogo, pagos, SEO o sitemaps.

```ts
// BOD-001 usa 19 fotos máx).
```

```ts
// lib/svg.ts — normalización en ingesta (Node sin DOM, regex/string)
type ConfigPaginaDisenador = {
  archivo: string;          // ruta local del SVG de diseñador
  keyR2: string;            // destino en R2
  anchoMm: number;          // se inyecta si el SVG no trae width en mm válido
  altoMm: number;           // se inyecta si el SVG no trae height en mm válido
  capaFotos: string;        // id exacto del <g>, p. ej. "fotos-editables" (sin espacios)
  capaTextos: string;       // id exacto del <g>, p. ej. "textos"
};
function normalizarSvgDisenador(svg: string, config: ConfigPaginaDisenador):
  { svg: string; zonas: string[]; textos: string[]; avisos: string[] };
// Errores nuevos: "zona-duplicada" | "contrato-mixto" | "sin-capas-editables"
// Sin capas amables con formas: no-op (piloto FIG-001 intacto).
```

Convenciones:

- Orden determinista = orden de documento dentro de cada capa amable.
- Duplicados geométricos (`x,y,w,h` + `transform` idénticos) frenan la página, no crean zonas encimadas en silencio.
- Página con error de normalización no se sube a R2 y conserva su key en `null` (el editor muestra aviso, nunca error); el seed continúa con el resto y el reporte lo marca.
- Guardar siempre serializa ambas páginas (el PUT reemplaza todo: guardar solo la visible borraría la otra).
- Al cambiar de página se limpia la selección de zona/texto.
- `code` sigue inmutable y es la única identidad en URLs del editor; `?t=` restaura ambas páginas.

## Plan de implementación

1. `lib/svg.ts`: `normalizarSvgDisenador()` + errores nuevos + slugify de textos. Verificación: contra los 2 SVG reales (p.1: 12+4=16 zonas y slugs `retrospectiva`, `2021`; p.2: 3 zonas y slug `lorem-ipsum-dolor-sit-amet`; `grep -c data:image` ≥ 1 (imágenes incrustadas conservadas); no-op con el piloto FIG-001).
2. `PlantillaSvg.tsx`: `medirCajaZona` transform-aware (técnica de `cajaRectEnSvg`) + `clipPath` clonando el marcador original. Verificación: `/es/editor/FIG-001-A-BETA` sin cambios visuales; los 4 diamantes de BOD-001 p.1 recortan en diamante (clip = marcador clonado, selección = bbox).
3. Migración `plantilla_svg_key_2` + `pagina?` en tipos/imagenes/ajustes (normalizado a 1 en `cargarReapertura`) + validación `1|2` en `app/api/customizations` (topes 20 intactos: 19 fotos máx). Verificación: `npm run build` pasa; un `?t=` viejo abre todo en página 1 sin error.
4. `lib/plantilla.ts`: carga de páginas como array + fallback local por página + validación mm/zonas por página. Verificación: sin SVG pág. 2 → editor de 1 página, sin error.
5. `scripts/seed.ts`: config BOD-001 (2 páginas, 279.4×215.9 mm) + normalizar → sanitizar → `validarContratoSvg` antes de subir + reporte impreso (zonas, textos, bytes base64 conservados, medidas respetadas/inyectadas). Página con error: no se sube, conserva `null`, el seed continúa. Verificación: `db:seed` 2x sin duplicar.
6. `EditorShell`: selector página 1/2 + estado y `svgRef` por página + reparto de `?t=` por `pagina`; Guardar serializa ambas páginas; al cambiar de página se limpia la selección. `uploads` sin cambios. Verificación: editar p.1, pasar a p.2 y guardar conserva p.1; `?t=` restaura ambas.
7. `lib/pdf.ts`: raster por página + `addPage` → PDF único 2 páginas. Verificación: cada página mide 279.4×215.9 ±1 mm, con las imágenes incrustadas del diseño visibles en el PDF.
8. i18n `editor.pagina.*` ES/EN, responsive (selector usable en 360px), `npm run build` + `npm run lint` en verde, capturas 360/768/1280 sin scroll horizontal.

## Criterios de aceptación

- [ ] `db:seed` 2x sin duplicar; el reporte lista zonas y textos por página y bytes base64 conservados.
- [ ] Cada página valida mm + ≥1 zona por separado; sin SVG pág. 2 el editor muestra 1 página sin error.
- [ ] Página 1: 16 zonas (12 rectángulos + 4 diamantes; el 13.º rect está duplicado en `410.28,126.84` y el dueño debe borrarlo en Illustrator: hasta entonces el seed reporta `zona-duplicada` y no sube esa página); página 2: 3 zonas.
- [ ] Los slugs generados son `retrospectiva`, `2021` y `lorem-ipsum-dolor-sit-amet`.
- [ ] Cada zona acepta foto recortada a su forma real (los diamantes recortan en diamante, no en caja).
- [ ] Cada `texto-editable-<slug>` es editable; lo no marcado no lo es.
- [ ] `zona-editable-1` de pág. 1 y de pág. 2 no colisionan (fotos, ajustes y keys R2 independientes).
- [ ] El PDF es único de 2 páginas, cada una 279.4×215.9 ±1 mm, con las imágenes incrustadas del diseño visibles tanto en el editor como en el PDF (`data:image` ≥ 1 en lo subido a R2).
- [ ] Guardar entrega `?t=` que restaura ambas páginas; editar p.1, pasar a p.2 y guardar conserva p.1 (el PUT fusiona, no reemplaza por página); un link viejo de 1 página abre sin error (todo en página 1).
- [ ] El piloto FIG-001-A-BETA sigue idéntico (normalización no-op, canvas sin regresión).
- [ ] Ningún string UI nuevo vive fuera de `messages/es.json` + `messages/en.json`.
- [ ] En 360px, 768px y 1280px no hay scroll horizontal (`scrollWidth <= innerWidth`).
- [ ] `npm run build` y `npm run lint` pasan en verde.
- [ ] El diff no toca home, categoría, página de producto, SEO ni sitemaps.

## Decisiones

- **Sí:** normalización en seed (no tolerancia en runtime). Descarta fallback en el editor (escondería los problemas al invitado y complicaría validación/paneles). El editor solo habla el contrato.
- **Sí:** diamantes como zonas de foto con clip de forma real (clon del marcador). Descarta bbox como clip (recortaría cuadrado, no diamante) y descarta pedir al dueño hornear rotaciones (fricción innecesaria pudiendo resolverlo en código).
- **Sí:** contorno de selección rectangular aunque la zona sea diamante. Solo afecta a la UI de selección; foto, clip y PDF usan la forma real. Descarta contorno con forma (costo sin beneficio de impresión).
- **Sí:** `plantilla_svg_key_2` como columna (no array). Descarta array JSON desde ya (sobrediseño para 2 páginas; la migración a array queda documentada para 3+).
- **Sí:** slugs de texto desde el contenido (recorte a ≤30 en límite de guion; cabe en el límite 64 del servidor). Descarta `t1, t2…` posicionales (menos estables y etiquetas genéricas en el panel).
- **Sí:** re-exportar puede re-encuadrar diseños guardados (decisión del dueño). Descarta mapeo por geometría (la parte más cara; innecesaria con este acuerdo).
- **Sí:** conservar las `<image data:>` de la capa de diseño inline (enmienda 2026-10-16). Son parte del diseño y deben verse en el editor e imprimirse en el PDF. Descarta eliminarlas (se perdían en editor y PDF) y descarta extraerlas a R2 (el raster del PDF dependería de CORS y podría fallar; el SVG autocontenido es más robusto a cambio de ~205 KB/435 KB por página).
- **Sí:** `uploads` intacto (la key con UUID ya es única entre páginas). Descarta prefijo `p1/p2` (churn sin beneficio: nada puede colisionar).
- **Sí:** página con error no se sube y conserva `null` (el seed continúa). Descarta fallar todo el seed (rompería el deploy por una plantilla) y subir parcial (el editor mostraría zonas rotas).
- **Sí:** `contrato-mixto` como error. Descarta mezclar sistemas con offset de N (impredecible para el dueño).
- **Sí:** Guardar fusiona ambas páginas. Descarta guardar solo la visible (el PUT last-write-wins borraría la otra).
- **No:** 3+ páginas, mapeo entre versiones, selección con forma, shrink por `tspan`, itálicas, subida de SVG por UI.

## Riesgos

| Riesgo | Mitigación |
|---|---|
| El dueño re-exporta con distinto orden y los IDs posicionales de fotos se renumeran | Aceptado (decisión): los textos van por slug estable; las fotos se re-encuadran |
| Regex sobre XML de Illustrator frágil ante anidamientos futuros | Solo hijos directos de las capas amables; cualquier otra estructura da `sin-capas-editables` en vez de adivinar |
| `getBBox`/matriz de un marcador degenerado falla o mide 0 | Misma guarda existente: sin caja medible no hay zona ni drop, el reporte lo lista |
| Raster 2 páginas pesado en móvil | Lado mayor limitado ya existe (`MAX_LADO_PX`); raster secuencial por página |
| El SVG base con imágenes inline pesa ~205/435 KB por página | Se sirve desde R2 y se conserva inline por seguridad del raster (sin CORS); el tope de lado mayor del PDF ya existe |
| `zona-editable-1` existe en ambas páginas y el shell los confunde | La `pagina` viaja en cada item de imagenes/ajustes (el servidor la valida `1\|2`); la key R2 ya es única por UUID |

## Lo que **no** está en este spec

- Tercera página o N páginas genéricas.
- Mapeo por geometría entre versiones de una plantilla.
- Contorno de selección con la forma real de la zona.
- Auto-shrink por línea en párrafos multi-`tspan`.
- Itálicas y pesos fuera del catálogo SPEC 2.4.
- Subida de SVG por UI y admin de plantillas.
- Cambios en `app/api/uploads`, firma mágica, rate-limit o topes.
- Cambios en home, categoría, producto, SEO o sitemaps.

Cada uno de esos, si llega, va en su propio spec.
